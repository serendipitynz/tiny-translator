# 先行事例と差別化

PLaMo 3 Translate の重み公開 (2026-11-05) の翌日に調べ、m-5 の配布判断 (TASK-25) のために 2026-11-10 に調べ直した。
調査には RustXNG (ローカルのメタ検索) と GitHub API (リポジトリ検索・README・リリースノート) を使った。

## 1. 先行事例

### 1.1 tanakh/plamo-translate-desktop (最も近い)

- https://github.com/tanakh/plamo-translate-desktop 。2026-11-05 作成、Apache-2.0。
- 2026-11-10 時点で v0.5.0。6 日で 6 回リリースしている。スター 130、外部からの PR も入り始めた (macOS 対応とブラウザ拡張のショートカット)。

| 版 | 日付 | 主な追加 |
|---|---|---|
| v0.1.0 | 11-05 | Windows x86_64 と Linux x86_64 の配布物 |
| v0.2.0 | 11-06 | Chrome / Edge 拡張 (選択範囲とページの翻訳。アプリの横に置くホストが翻訳する) |
| v0.3.0 | 11-06 | Intel NPU 版の Windows パッケージ、デバイスの速度を測って選ぶ機能 |
| v0.4.0 | 11-07 | **macOS (Apple Silicon、macOS 13.3 以降、Metal) の dmg**。拡張だけでブラウザ内で翻訳するエンジン (wllama、WebGPU) |
| v0.5.0 | 11-10 | アプリの自動更新、モデルの新しい版の検出と更新、モデルの置き場所の変更、UI の拡大率 |

- Rust + GPUI。llama.cpp を `llama-cpp-2` でプロセス内に組み込み、GGUF を CPU (AVX2 / AVX-512)、Vulkan、Metal、OpenVINO (Intel NPU) で動かす。
- 設計書 (`docs/design.md`) §1 は今も主対象を Windows、副対象を Linux とし、macOS を「Non-goals for now」に残している。
  ただし v0.4.0 からリリースに macOS の dmg が入っており、実態は 3 OS 対応である (公証はしていない)。
- 持っている機能:
  - 53 言語の翻訳。既定の翻訳先は「日本語 ⇄ 英語 (自動)」
  - 貼り付けで翻訳、入力が止まったら翻訳、ストリーミング表示、停止、速度と残り時間の表示
  - 日本語の常体・敬体、文脈、用語集 (`source = target` を 1 行ずつ。用語集は保存される)
  - 長文の段落分割と、前の段落の対訳を履歴としてプロンプトに入れる方式。出力の繰り返しを検知して小さく分けて訳し直す
  - 原文と訳文の同期スクロールと、対応する段落の選択
  - モデル管理 (0.8B〜31B、量子化の選択、再開できるダウンロード、SHA-256 の照合、Hugging Face から新しいファイルと新しい版を見つける、置き場所の変更)
  - Chrome / Edge 拡張 (選択範囲の翻訳、ページ翻訳でリンクと書式を保つ)。拡張用のホストは 5 分使わないと終了してメモリを解放する。アプリが無くてもブラウザ内で 0.8B と 2B を動かせる
  - アプリの自動更新、英語と日本語の UI、Light / Dark、UI の拡大率
- 持っていない機能: 翻訳履歴、起動時のクリップボード翻訳 (グローバルホットキーでの翻訳は設計書 §9 の「Future idea」のまま)、
  アプリでの Markdown・JSON・HTML の構造保持 (HTML の構造保持はブラウザ拡張のページ翻訳だけ)、
  優先順位を設定できる翻訳先の決定、アプリ本体でのモデルの自動解放
- 参考になる実測と知見:
  - 2B Q4_K_M を Ryzen 9 9950X の CPU で動かしたとき、生成は約 19.5 tok/s (メモリ帯域が律速)
  - macOS の GPU では GGUF をメモリマップしたまま使うので、0.8B のピークメモリが約 760 MB から約 200 MB に下がった (速度は同じ)。
    v0.4.0 のリリースノートの値で、どの指標かは書かれていない。doc-1 §4.5 の実測では、mmap した重みはアクティビティモニタの「メモリ」には出ないが、
    使用済みメモリは RSS とほぼ同じだけ増える
  - インライン要素を番号付きのタグ (`<a i="2">`) にして渡すと、0.8B と 2B でタグの位置と順序の入れ替えが保たれた (HTML と Markdown で確認)
  - 小さいモデルは長い出力で繰り返しや抜けを起こすので、翻訳単位を小さく保つ

## 2. 本アプリが差別化できる点

2026-11-06 の評価と、2026-11-10 の状況を並べる。

| 差別化の軸 | 2026-11-06 の評価 | 2026-11-10 の状況 |
|---|---|---|
| macOS (Apple Silicon) で単体で動く | tanakh 版は対象外。追いつく見込みは高い | **失った。** tanakh 版 v0.4.0 が dmg を配布し、§1.4 の macOS アプリも複数ある |
| 翻訳履歴と全文検索 | どの先行事例も持たない。見込み中 | tanakh 版には無い。tamanyan 版が持つが配布物は無い |
| Markdown・JSON・HTML の構造保持翻訳 | tanakh 版はブラウザ拡張の HTML だけ。見込み中 | 変わらず。tanakh 版はタグ方式を Markdown でも確かめており、アプリへ入れる素地はある |
| 優先順位による翻訳先の決定 | tanakh 版は日本語 ⇄ 英語の自動だけ。見込み高い | 変わらず |
| 起動時のクリップボード翻訳 | tanakh 版は計画のみ。見込み高い | tanakh 版は計画のまま。他のアプリはショートカットで選択範囲を訳す方式で同じ用途を満たす |
| 翻訳エンジンの自動解放でメモリを返す | tanakh 版はアプリ本体では解放しない。見込み中 | 変わらず |
| snz-design の見た目 | オーナーの他のアプリとそろう | 変わらず (オーナー固有) |

逆に、tanakh 版にあって本アプリに無いもの: 用語集・文脈・常体と敬体の入力、ブラウザ拡張、アプリとモデルの自動更新、31B の選択、
Linux 対応、NPU、同期スクロール。

## 3. 判断

- **自分用には作る価値がある** (2026-11-06 オーナー判断で継続)。当時は主に使う M1/M2 で動く先行アプリが無かった。今も §2 で残っている機能は tanakh 版に無い。
- **配布の価値は 11-06 時点より下がった (2026-11-10 の再調査)。** macOS 対応という最大の差は無くなり、残る差 (履歴・構造保持翻訳・翻訳先の優先順位・
  起動時のクリップボード翻訳・自動解放) は機能の差だけである。tanakh 版は数日おきにリリースを重ね、外部の PR も受けている。
  配布するなら、署名・公証、更新の仕組み、利用者からの問い合わせへの対応を、それに見合う利用者が見込めないまま負うことになる。
- **配布する (2026-11-10 オーナー判断、TASK-25)。** 本アプリはオーナーが自分で使うために作っており、配布は利用者を得るためではない。
  オーナーの他のアプリ (snz-studio、mallow) も同じく自分用に作って配布している。先行事例との差の大小は、配布するかどうかの理由にしない。
  配布物には macOS の署名・公証 (TASK-26) と自動更新 (TASK-30) を入れる。
- 判断のときに比べた 3 つの選択肢:

| 選択肢 | 得るもの | 負うもの |
|---|---|---|
| 配布する (TASK-26 へ進む) | 構造保持翻訳や履歴を求める利用者に届く | 署名・公証と配布物の保守、更新の仕組み、問い合わせ対応。tanakh 版との機能差は追いつかれやすい |
| 配布しない (自分用に使い続ける) | 保守は自分の用途の範囲で済む | 他の人には届かない (ソースは公開のまま読める) |
| 先行事例へ機能を提案する | 最も使われているアプリで機能が使えるようになり、自分も tanakh 版へ乗り換えられる | 提案の採否は tanakh 版の作者が決める。Rust + GPUI での実装し直しになる |
