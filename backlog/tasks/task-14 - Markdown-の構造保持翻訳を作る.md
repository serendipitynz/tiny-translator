## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. 本番依存 pulldown-cmark 0.13 (default-features = false。依存は bitflags・memchr・unicase) をオーナーの承認を得て追加する (doc-1 §3)。
2. src-tauri/src/tags.rs: 番号付きのタグの組み立てと戻しを形式に依らず持つ (HTML の TASK-16 も使う)。強調・リンクのような中身を訳す要素は <em i="1">…</em> の対、インラインコード・自動リンク・裸の URL は <code i="2">原文</code> (中身は訳文のものを捨てて原文へ戻す)、ハードブレーク・インライン HTML・脚注の参照は <br i="3"/> のような空要素にする。訳文のタグの番号・名前・入れ子が原文と合わなければ戻さない (順序の入れ替えは許す)。
3. src-tauri/src/markdown.rs: pulldown-cmark の位置付きイベントで、段落・見出し・リスト項目・表のセル・引用の中のインラインの並びを翻訳単位にし、それ以外 (コードブロック・HTML ブロック・front matter・リンクの定義・記法の記号) は原文の位置のまま残す。翻訳単位の文字列は原文をそのまま切り出し (エスケープを保つ)、要素だけをタグにする。訳文は原文の該当範囲へ差し込む。段落の訳文の改行には引用・リスト項目の続きの行の接頭辞を付け、見出しと表のセルでは改行を空白にし、セルでは | をエスケープする。文字を含まない翻訳単位 (数値だけのセルなど) は訳さない。
4. src-tauri/src/document.rs: 翻訳単位の列 (原文のまま残す部分と訳す部分) を順に訳す流れに一般化し、プレーンテキストと Markdown が共有する。タグ付きの翻訳単位はタグを隠して流し、終わったら元の記法へ戻した訳文で置き換える。タグが合わない・長すぎて分ける必要がある・繰り返したときは、タグを外した原文で訳し直す (TASK-13 の文の単位での訳し直しに乗る)。
5. translate command に format ("text" / "markdown") を足す。形式の選択欄は TASK-17 なので、画面は当面 "text" を送る。
6. 代表的な Markdown の入出力を固定したテスト (偽の翻訳エンジン) と、tags・markdown の単体テストを書く。実機 (M2・2B) で Markdown を訳してタグが保たれる様子を確かめる。
7. doc-1 §7.1 にタグの形と戻せないときの扱いを書く。

## 実装 (TASK-14)

- 本番依存 pulldown-cmark 0.13.6 を `default-features = false` で追加した (オーナー承認済み。新しく入るのは unicase だけ)。
- `src-tauri/src/markdown.rs`: 位置付きのイベントで、ブロックの中のインラインの並びを翻訳単位にし、それ以外は原文から写す。
  `src-tauri/src/tags.rs`: 番号付きのタグの組み立て・戻し・流れてくる訳文からのタグの除去を形式に依らず持つ (HTML の TASK-16 でも使える形)。
  `src-tauri/src/document.rs`: 原文のまま残す部分と翻訳単位の列を順に訳す流れにし、プレーンテキストと Markdown が共有する。
- `translate` command に `format` ("text" / "markdown") を足した。形式の選択欄は TASK-17 なので、画面は当面 "text" を送る。
- 決めたこと (doc-1 §7.1 の「Markdown (TASK-14)」に記録):
  - 記法を書き直す (pulldown-cmark-to-cmark のような) 方式ではなく、原文の翻訳単位の範囲へ訳文を差し込む方式にした。記法が入力のまま残り、追加のクレートも要らない。
  - 翻訳単位の文字列は Text イベントの中身ではなく原文から切り出す。イベントの中身はエスケープ (`\*`、表の `\|`) が外れていて、訳文をそのまま戻すと記法になってしまうため。
  - インラインコード・URL はタグの中に原文の中身を見せて渡し (`<code i="1">npm i</code>`)、訳文の中身は捨てて原文へ戻す。中身を隠すと文の意味がモデルに伝わらないため。
  - タグが戻せないとき・繰り返したとき・1,024 トークンを超えるときはタグを外して訳し直し、そのとき直前の対訳は入れない。
  - 強調の `_` は `*` で戻し、`[label]` / `[label][]` のリンクは `[訳文][label]` で戻す。
  - 残る制約: `これは**「強調」**です` のように、中身が括弧・句読点で始まるか終わる強調は CommonMark の規則で強調にならない (原文に無い空白を足さないと直せないので、そのままにした)。

## レビューでの修正 (1 回目、Codex)

- [P2] `[label][]` のリンクが段落の末尾にあると、pulldown-cmark がリンクの範囲から外す `[]` が翻訳単位の後に原文として残り、`[ホーム][Home][]` になった。翻訳単位の範囲を消費した位置まで広げ、回帰テスト (`a_collapsed_link_that_ends_a_unit_comes_back_once`、タグを外した訳し直しの場合も) を足した。
- [P2] タグを外した訳し直しでは、インラインコードと URL がただの文字列としてモデルへ渡り、訳されうる。間に「そのままの要素と空要素のタグだけを残した文字列」での訳し直しを挟み、それも戻せないときだけタグを外すようにした (テスト 4 件追加)。1,024 トークンを超える翻訳単位はタグのまま文で分けられない (対のタグが文をまたぐ) ので、タグを外して訳す制約として doc-1 §7.1 に書いた。
- これで `cargo test` は 114 件。上の「109 件」はこの修正の前の数字。

## レビューでの修正 (2 回目、Codex)

- [P2] (1 回目と同じ趣旨の再指摘) 対の要素が無く中間の段階が無い翻訳単位 (``Use `hello` now.``) や、中間の段階も失敗した翻訳単位では、タグを外した訳文でコード・URL が変わりうる。オーナー判断 (2026-11-08) で、タグを外した訳文に、そのままの要素の原文が書いたとおり同じ数だけ含まれていなければ、その翻訳単位を原文のまま残すことにした。1,024 トークンを超える翻訳単位もこの確認を通る。doc-1 §7.1 を改めた。
- これで `cargo test` は 116 件。
