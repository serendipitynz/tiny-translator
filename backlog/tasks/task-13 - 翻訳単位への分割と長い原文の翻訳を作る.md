## Description

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. src-tauri/src/units.rs: プレーンテキストを空行で翻訳単位に分ける (前後と間の空白は原文のまま残す)。コンテキスト長に収まらない翻訳単位は文の境界でまとめ直す (文に収まらなければ改行、最後は文字数で分ける)。文の単位への分割も同じ規則で持つ。
2. src-tauri/src/repetition.rs: 訳文の末尾が同じ文字列の繰り返しになったことを文字単位で検知する。原文自体が持つ繰り返し (罫線など) より十分長いときだけ繰り返しとみなす。
3. src-tauri/src/translate.rs: プロンプトに直前の対訳を公式 chat_template.jinja の履歴の形 (input/output の組) で入れる。llama-server の /tokenize でトークン数を数える。ストリームを途中で打ち切れるようにする。
4. 長い原文の翻訳の流れ (Model トレイトで翻訳エンジンを差し替え可能にし、偽の翻訳エンジンで単体テスト): 翻訳単位を順に訳し、繰り返しを検知したら打ち切って文の単位で訳し直す。それでも繰り返す 1 文は最初の 1 回までを残す。
5. 画面へは「追記」と「ここまでの訳文で置き換え」の 2 種類を Channel で送り、src/lib/translate.ts が訳文全体にまとめて App.svelte へ渡す。
6. doc-1 §4.3 / §7.3 に決めたこと (履歴の形・予算・繰り返しの閾値) を書く。実機で長い原文を訳して確かめる。

7. (実機の結果で追加) 1 つの翻訳単位を分けた部分の間で改行の無い区切りは、訳文の前後の文字で空白の有無を決める (日本語の原文から英訳したとき文が詰まるため)。

## 実装 (TASK-13)

- 分割は `src-tauri/src/units.rs` (空行で段落、文、行、上限トークン数に収める `fit`)、繰り返しの検知は `src-tauri/src/repetition.rs`、
  翻訳単位を順に訳す流れは `src-tauri/src/document.rs`。翻訳エンジンは `document::Model` トレイトの向こうにあり、単体テストは偽の翻訳エンジンで流れ全体を確かめる。
- 決めたこと (doc-1 §4.3・§7.3 に記録):
  - 直前の対訳は PFML3 の `context` ではなく、公式 `chat_template.jinja` の履歴の形 (前の原文の input と訳文の output を、翻訳する原文の input の前に置く) で渡す。
    `context` は自由な参考テキストの欄で、原文と訳文の区別がモデルに伝わらない。HF の 2B の `chat_template.jinja` を読んで確認した
    (GGUF に埋め込まれたテンプレートは履歴を持たない簡略版だが、アプリは `/completion` に自分で組んだ文字列を渡すので影響しない)。
  - 予算: 1 プロンプトの原文 1,024 トークン (コンテキスト長 8,192 の 1/8)、対訳の組 2,048 トークン (1/4)。`engine::CONTEXT_TOKENS` から導く。
  - トークン数は `/tokenize` で数え、バイト数が上限以下なら数えない。
  - 繰り返し: 256 文字以内の周期が 3 回以上・64 文字以上・原文自身の最長の繰り返しの 2 倍以上。文字単位で調べる。
  - 訳し直しの 1 文がまた繰り返したら、1 回目の終わりまでを残して次へ進む (先行事例のような repeat penalty での再試行はしない。
    temperature 0 の決定性を保ち、要求の形を 1 つに保つため)。
  - 画面へは Channel で `["append", text]` と `["replace", 訳文全体]` を送り、`src/lib/translate.ts` が訳文全体にまとめて App.svelte へ渡す。
    取り消しはまれなので、置き換えは差分ではなく訳文全体にした。
- 実機で見つけて直した不具合: 日本語の原文は文の間に空白が無いので、文の単位で訳し直した英訳が `kikiki.So, so` のように詰まってつながった。
  1 つの翻訳単位を分けた部分の間は、改行の無い区切りを訳文の文字で決める (前後とも漢字・かな・全角記号なら空白なし、それ以外は空白 1 つ)。

## 確かめたこと

- `cargo test` (80 件。うち新規は units 15・repetition 6・document 15・translate 4)、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`、
  `pnpm test` (44 件)、`pnpm check`、`pnpm lint` が通る。
- 実機 (MacBook Air M2・2B Q4_K_M、アプリと同じ引数の llama-server に一時テストから接続):
  - 3 段落の英日: 1.4 秒。空行・字下げ・末尾の改行が原文どおり残った。
  - 英語 1,702 トークンの 1 段落 (120 文): 文の境界で 2 つに分け 49 秒。120 文すべての訳が出た。似た構造の文の連続でも繰り返しの誤検知なし。
  - 日本語 2,482 トークンの 1 段落 (150 文): 3 つに分け 71 秒。英訳の文が詰まる箇所 0。150 文すべての訳が出た (熱で遅くなった状態の再実行では 235 秒)。
  - 打ち切り (20 断片で切る) の 0.93 秒後に送った次の要求が 0.17 秒で返った (接続を閉じれば llama-server は次をすぐ受け付ける)。
  - 「あああ…いいい…。それで、それで、それで、どうなったの？」の日英で繰り返しを検知し、2 文に分けて訳し直した。
    Buffalo の文、Markdown の表、16 進の並びでは誤検知なし。
  - `/tokenize` は API キーを要求し (無いと 401)、英語・日本語・絵文字・𠮷 などの 8 例すべてでトークン数 ≤ バイト数。
- 測っていないこと: アプリの画面での長い原文の翻訳 (Rust の command と画面側の受け渡しは単体テストのみ)、0.8B と 8B、Windows。
