## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. 置き場所はモーダル (doc-9 §6.6 の作業) とする (2026-11-09 オーナー判断)。ヘッダーの履歴ボタンで開き、1 件を選ぶと画面へ戻して閉じる。
2. 戻す言語は保存された「使った言語」を選択欄へ指定する。翻訳元が判定なし (NULL) のときだけ自動判定、選択欄に無い値も自動へ落とす。形式の選択欄は触らない (2026-11-09 オーナー判断)。翻訳中に選んだら翻訳を停止してから戻す。
3. 部品: ui/Modal.svelte (焦点の預けと返却・閉じ込め・Escape は一番内側だけ・覆いの押下・処理中は閉じない)、ui/TextInput.svelte (1 行入力。IME の変換中は値を確定しない)、Button に破壊的操作の変種、lucide の trash-2。
4. HistoryModal.svelte: 一覧 (doc-9 §6.1 の行の並び。狭い幅ではカードの並び) の見出し域に検索欄・件数・全件削除、行ごとに 1 件削除。空は絞り込みの有無で語を分け、絞り込みの空には検索語をクリアする操作を置く。読み込み中・失敗は空と分ける。
5. 全件削除は破壊前確認 (§5.7) のモーダルを重ね、既定の焦点は取り消し側。件数を述べるため Rust に history_count を足す。
6. 純粋な部分 (戻す選択・言語の表示・日時・空の語) は src/lib/history.ts に置き vitest で試す。画面は vite の開発サーバーを内蔵ブラウザで開き、Tauri の IPC を差し替えて確かめる。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
置き場所はモーダル、戻す言語は使った言語の指定とした (どちらも 2026-11-09 オーナー判断。doc-1 §9 に追記)。

- 全件削除の確認で消える件数を述べるため、Rust に history_count を足した (History::count をテスト専用から本番の API へ移した)。検索結果の件数では、絞り込み中に全件の数を言えない。
- 削除後のフォーカスは、消えた行の位置に来た行の削除ボタンへ移す (無ければ上の行、それも無ければ検索欄)。続けて消すときに 1 キーで済むため。
- 件数と空の語は「表示中の一覧が答えた検索語」から作る。入力中や検索の失敗時に、古い一覧へ新しい検索語の件数が付いて見えるのを避けた。履歴自体が 0 件なら、検索語があっても「まだありません」の語を出す。
- 一覧の原文・訳文は 2 行で切り詰め、改行は空白へ畳む (見出しと空行で 2 行を使い切らないため)。全文は選んで画面へ戻すと読める (doc-9 §6.1 の到達手段)。

確認したこと:
- pnpm check / pnpm lint / pnpm test (58 件、history.test.ts の 13 件を含む)、cargo fmt --check / clippy -D warnings / cargo test (187 件) が通る。
- Vite の開発サーバーを内蔵ブラウザ (Chromium) で開き、Tauri の IPC をモックに差し替えて操作した。一覧 (行の並び、幅 420px ではカードの並びで横スクロールなし)、絞り込みの空 (条件の語と「検索語をクリア」)、絞り込みなしの空、読み込みの失敗 (前の一覧を残して理由を表示)、1 件削除と削除後のフォーカス、全件削除の確認 (既定の焦点はキャンセル、Escape は確認だけを閉じて全件削除へ焦点を返す、処理中は Escape で閉じない)、Tab がモーダルの中で一周すること、1 件を選ぶと原文・訳文・翻訳元 fr・翻訳先 en が戻り形式は自動のまま、焦点が履歴ボタンへ戻ること。

確かめていないこと (オーナーの確認待ち):
- 実窓 (Tauri の WKWebView と本物の SQLite) での一連の操作。
- IME の変換中に検索欄が検索しないこと、Escape が変換の取り消しになること (合成イベントを作れなかった)。
- 翻訳中に 1 件を選んだときの停止 (モックに翻訳が無い)。処理は停止ボタンと同じ手順。
